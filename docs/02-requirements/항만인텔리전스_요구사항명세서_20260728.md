# 항만/선박 인텔리전스 서비스 — 개발 요구사항 명세서 (SRS)

| 항목 | 내용 |
|---|---|
| 문서명 | 항만/선박 인텔리전스 서비스 요구사항 명세서 |
| 버전 | v1.0 (2026-07-28) |
| 작성 기준 | 태웅로직스 김태완 대리 피드백(KakaoTalk) + 북마크 캡처 |
| 대상 독자 | 개발 담당(본인) |
| 목적 | 피드백을 **구현 가능한 요구사항**으로 전환 — 착수용 스펙 |

> 표기 규칙: `[확정]` 대화로 합의된 요건 / `[제안]` 개발자 판단으로 채운 기본값(변경 가능) / `[확인필요]` 결정·검증 필요. 수용기준은 체크박스로 표기.

---

## 1. 개요

### 1.1 목적
국내외 컨테이너 터미널의 **선석배정·선박위치·항만 혼잡도·스케줄** 정보를 통합 조회하는 대시보드. 법인 및 계열사 본사 배포 대상.

### 1.2 범위

| 구분 | 내용 |
|---|---|
| In scope | Port Insight 검색, 국내 선석배정 터미널 확대, 국내/해외 탭 분리, 해외 터미널 스케줄, Ship Schedule 3-뷰 + 성능개선 |
| Out of scope (차후) | 로그인 필요 외부 서비스 연동, 상용 API 유료 연동(tradlinx 등), 사용자 계정/권한 체계(현 시점 미언급) |

### 1.3 용어 정의

| 용어 | 설명 |
|---|---|
| LOCODE | UN/LOCODE. 항구 표준코드 (예: 미국 서배너 = USSAV) |
| ETB / ETD / ETA | 접안예정 / 출항예정 / 입항예정 일시 |
| ATB | 실접안일시 |
| CCT | 반입마감(Cargo Closing Time) |
| 양하 / 적하 | 하역(Discharge) / 선적(Loading) 물량 |
| POL / POD | 선적항(Port of Loading) / 양하항(Port of Discharge) |
| ICON | 인천항 통합 조회(선광/한진/E1/인천/국제여객) |
| 통합수집 | 여러 터미널을 한 소스에서 묶어 수집하는 방식(ICON 등) |

## 2. 시스템 개요

### 2.1 현행 기능 구성

| 기능 | 현황 | 검증 결과 |
|---|---|---|
| Port Insight | 항만 혼잡도 지도/지표(섹션2에 급변 항만 노출) | 데이터 신뢰도 문제없음 |
| 선석배정 | 국내 **9개 터미널 217건** 자동수집, 터미널별 시트 엑셀 산출 | 신뢰도 긍정 |
| 선박위치 / 경로 시뮬레이션 | 메뉴 존재, 동작 | 개선요청 없음 |
| Ship Schedule | (해외) 미흡 → 신규/개선 대상 | — |

### 2.2 목표 구조 (내비게이션)

```
[상단 탭] 국내 | 해외
  └ 국내
      ├ Port Insight (검색 추가)
      ├ 선석배정 (터미널 확대)
      ├ 선박위치 / 경로 시뮬레이션
  └ 해외
      ├ Ship Schedule (Route / Vessel / Port)
      ├ 해외 터미널 현황
      ├ (Port Insight 해외 확장 여부 = 확인필요)
```

### 2.3 데이터 수집 파이프라인 (목표)

```
[터미널 사이트/이미지]
   → 수집기(스크래핑 · OCR)  ── 사이트별 파서
   → 정규화(공통 스키마 매핑) ── 중복/변경 감지(해시)
   → DB 적재(TB_BERTH_SCHEDULE)
   → ① 대시보드 조회   ② 통합 엑셀 산출(터미널별 시트)
   * 일 1회 이상 배치 자동 수집
```

## 3. 기능 요구사항 (Functional Requirements)

### FR-01 · Port Insight 관심 포트 검색  `[확정]` · **P1**

- **배경**: 유일한 개선요청 — 궁금한 포트를 검색해 지도에서 당겨(포커스) 보고 싶음.
- **상세 요건**
  - 항구명(국문/영문) 및 **LOCODE**로 검색.
  - 2자 이상 입력 시 **자동완성** 드롭다운.
  - 결과 선택 시: 지도 **pan + zoom(도시레벨)**, 해당 포트 마커 강조, 우측 **상세 패널** 오픈(기존 섹션2 혼잡 지표 재사용).
- **입력 / 출력**

  | 입력 | 출력 |
  |---|---|
  | 검색어(항명/LOCODE) | 자동완성 후보 리스트 → 선택 시 지도 이동 + 상세 패널 |

- **화면 요소**: 검색창, 자동완성 드롭다운, 지도, 포트 상세 패널.
- **수용기준(AC)**
  - [ ] "Savannah" 또는 "USSAV" 입력 시 자동완성에 해당 포트 노출
  - [ ] 선택 시 지도가 해당 포트로 이동·확대(응답 < 2초)
  - [ ] 상세 패널에 혼잡 지표(섹션2 동일 항목) 표시
  - [ ] 결과 없을 때 "검색 결과 없음" 안내
- **의존성**: 포트 마스터(LOCODE·좌표) 데이터 필요.

### FR-02 · 선석배정 수집 터미널 확대  `[확정]` · **P1**

- **배경**: "터미널 추가해달라" + 김태완 북마크/URL 제공.
- **상세 요건**
  - 수집 대상 = **5.1 터미널 마스터** 기준. 현행 9개 → 신규 8곳 추가, 확인 4곳 매핑 후 반영.
  - 터미널별 `SOURCE_TYPE`(SCRAPE/OCR)에 맞는 **파서 모듈** 구현(플러그인 구조 권장).
  - **ICON 통합 중복** 방지: 인천 개별(ICT·HJIT·SNCT)이 ICON에 포함되면 개별 수집 제외.
- **수용기준(AC)**
  - [ ] 신규 터미널 8곳(HBCT·BPT·DPCT·BCT·KITL·PCTC·PNCT·DDCT) 일 1회 자동 수집·저장
  - [ ] 통합 엑셀에 터미널별 시트로 출력(기존 포맷 유지)
  - [ ] ICON 중복 터미널 중복 저장 안 됨(dedup 키 적용)
  - [ ] 수집 실패 시 에러 로그 + 재시도(백오프), 부분 실패해도 나머지 정상 저장
  - [ ] 신규 터미널 추가 시 **코드 수정 최소화**(마스터 등록 + 파서만 추가)
- **의존성**: 5.1 마스터, 5.2 스키마, 파서 프레임워크.

### FR-03 · 국내/해외 탭 분리  `[확정]` · **P1**

- **상세 요건**: 상단 `국내 | 해외` 탭. 라우팅·데이터 소스 분리. 탭 상태 유지(딥링크/URL 반영 권장).
- **수용기준(AC)**
  - [ ] 상단 탭 전환 시 국내/해외 화면·데이터 분기
  - [ ] 새로고침/공유 링크로 특정 탭 직접 진입 가능
  - [ ] `[확인필요]` Port Insight·선박위치도 국내/해외 분기할지 결정 반영
- **의존성**: FR-04, FR-05(해외 탭 콘텐츠).

### FR-04 · 해외 터미널 스케줄/현황  `[확정]` · **P1**

- **배경**: "해외도 되냐" → 해외 탭 별도 구현.
- **상세 요건**: LOCODE 기반 해외 포트 조회. searates 구조 벤치마크(§부록). 데이터 소스·수집방식은 §8-5 결정 필요.
- **수용기준(AC)**
  - [ ] 해외 포트(LOCODE)로 스케줄/현황 조회 가능
  - [ ] 국내와 동일한 UI 패턴으로 표시
  - [ ] `[확인필요]` 데이터 소스 확정(스크래핑/OCR/공개API)
- **의존성**: FR-05, NFR-01.

### FR-05 · Ship Schedule 3-뷰 + 속도 개선  `[확정]` · **P1(핵심)**

- **배경**: 김태완 실사용 패턴(searates). 최대 불만 = **느림**.
- **상세 요건 — 3개 조회 뷰**

  | 뷰 | 입력 | 출력(주요 컬럼) |
  |---|---|---|
  | **Route** | POL, POD, 출발일, 조회주(weeks) | 선사, 모선/항차, ETD/ETA, 소요일, 환적 여부·환적항 |
  | **Vessel** | 모선명 / IMO | 현재 위치(지도), 예정 기항지, ETA/ETD |
  | **Port** | LOCODE | 해당 포트 입·출항 스케줄, 혼잡/현황 |

- **수용기준(AC)**
  - [ ] 3개 뷰 탭 제공, 각 입력값으로 조회 동작
  - [ ] Route 결과에 환적 여부·소요일 표시
  - [ ] Vessel 조회 시 지도에 현재 위치 표시
  - [ ] **성능은 NFR-01 충족**(핵심 합격 조건)
- **의존성**: NFR-01(성능), 해외 데이터 소스.

## 4. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01 · 성능 (Ship Schedule)  **P1(핵심)**
- **배경**: searates "너무 느림" → 차별화 포인트.
- **목표치** `[제안]`

  | 지표 | 목표 |
  |---|---|
  | 초기 화면 로드 | < 2초 |
  | 스케줄 조회 응답 | < 3초 (캐시 히트 시 < 1초) |
  | 자동완성 응답 | < 300ms |

- **전략** `[제안]`: 사전수집 배치 + 서버 캐시(Redis) + 비동기/지연 로딩 + 서버 페이지네이션 + 조회 조건별 캐시 키.
- **AC**: [ ] 상기 목표치를 대표 시나리오(주요 항로·포트)에서 충족.

### NFR-02 · 데이터 수집/자동화
- 일 1회 이상 배치(현행 "매일 오전 자동수집" 유지).
- 사이트 구조 변경 시 **파서 단위 격리**(한 곳 깨져도 전체 중단 방지).
- 수집 이력·실패 로그 보관.

### NFR-03 · 데이터 정확성/검증
- 원본 대비 정합성 확인 절차(§8-3). 수집값 이상치(널·음수 물량 등) 검출 규칙.
- 변경 감지: 원본 행 해시(`SRC_ROW_HASH`)로 신규/변경/삭제 구분.

### NFR-04 · 확장성/유지보수
- 터미널 추가가 **설정 + 파서 추가**로 끝나는 구조(하드코딩 지양).
- 국내/해외 공통 스키마로 정규화.

## 6. 화면 설계 요건

### 6.1 전체 내비게이션
- 상단 1차 탭: `국내 | 해외`.
- 국내 하위: Port Insight / 선석배정 / 선박위치·경로.
- 해외 하위: Ship Schedule(Route·Vessel·Port) / 해외 터미널.

### 6.2 Port Insight — 포트 검색 (FR-01)

| 항목 | 유형 | 설명 |
|---|---|---|
| 검색창 | Text + 자동완성 | 항명/LOCODE, 2자↑ 제안 |
| 검색결과 | Dropdown | 항명·LOCODE·국가 표시 |
| 지도 | Map | 선택 포트로 pan/zoom, 마커 강조 |
| 상세패널 | Panel | 혼잡지표(섹션2 재사용), 대기선박 등 |

### 6.3 Ship Schedule — 3-뷰 (FR-05)

| 뷰 | 입력 항목 | 결과 컬럼(예) |
|---|---|---|
| Route | POL, POD, 출발일, weeks | 선사, 모선/항차, ETD, ETA, 소요일, 환적 |
| Vessel | 모선명 / IMO | 현재위치(지도), 다음 기항지, ETA/ETD |
| Port | LOCODE | 입출항 스케줄, 현황 |

## 8. 미결 / 결정 필요 (Open Issues)
