# 화면 기획 — 화물 추적 (cargo.html)

**v2.0 · 2026-08-19** (v1.0 2026-07-27 유니패스 통관조회 기준 — 전면 대체)
근거: `cargo.html` · `js/cargo.js` 실측. 설계 배경은 `docs/03-architecture/화물추적_선사직접조회_설계.md`,
고도화 근거는 `docs/03-architecture/화물추적_고도화_설계_2026-08-19.md`.

> **v1.0 과 무엇이 달라졌나** — v1.0은 관세청 유니패스 **통관 진행** 조회 화면이었다. 2026-08-11에
> **유니패스 통관조회를 화면에서 제외**(사용자 결정)하고 선사 트래킹 API 직접 조회로 목적 자체를 바꿨으며,
> 2026-08-19에 레이아웃을 **관제 콘솔**로 재편했다. v1.0의 MBL/HBL 토글칩·연도 선택·통관 타임라인은
> 화면에 없다(Edge Function `track` 과 `server.py /api/track` 경로는 보존만 — status 헬스체크에서만 호출).

## 1. 목적

MBL / AWB 번호 하나로 **선사 운송 이벤트를 직접 조회**하고, 중요한 화물은 **등록해두면 자동으로 감시**한다.
유료 서비스(KLNET LogisView 구독)가 하던 일을 무료 경로로 대체하는 것이 목표다.

| 축 | 내용 |
|---|---|
| 즉시 조회 | 실조회 6사(ONE·COSCO·SM상선·Evergreen·SITC·ZIM) — Edge Function `carrier-track` |
| 미지원 선사·항공 | 번호로 선사/항공사를 자동 감지해 **공식 추적 페이지 딥링크**로 안내(SCAC 15사·AWB 10사) |
| 자동 감시 | 등록분을 스케줄러가 매일 08:20·20:20 조회 → ETD/ETA·터미널 일정 변경 시 이메일 |
| 교차검증 | 선사 값 ↔ 국내 16터미널 선석 데이터(`bs_vessel_calls`) 대조 — 국내 구간 보완 |

## 2. 레이아웃 (와이어)

```
[공통 헤더 — 화물 추적 활성]
[타이틀] 화물 추적 — 선사 직접 운송 추적
         데이터: 선사 트래킹 API 직접 조회(6사) · 그 외는 자동 감지 후 공식 추적 딥링크

[SECTION 01] 화물 조회 콘솔                                    ← 2열 콘솔
┌───────────────┬─────────────────────────────────────────────┐
│ ◀ 좌측 레일(고정)   │ 우측 결과 영역                              │
│ ① 화물 조회        │ (조회 전) 빈 상태 안내 카드 ⌖               │
│   [번호 입력____]  │ ─────────────────────────────────────────  │
│   [   조회   ]     │ (조회 후) ■ 운송 관제 티켓 1장              │
│   AWB/선사 감지 힌트│   헤더: B/L · 선사 · 상태배지 · 본선 · [추적 등록]│
│ ② 자동 감시        │   SUMMARY  : 요약 칼럼 + Voyage Canvas(SVG) │
│   감시 N건 요약     │   TERMINAL : 국내 터미널 교차검증(조건부)    │
│   [감시 그리드 ↓]  │   GATE     : 컨테이너 × 9슬롯 게이트 그리드  │
│ ③ [채널 서랍 열기] │   HISTORY  : 컨테이너별 전체 이력(접기)      │
│                   │   푸터     : 데이터 시점 · 출처 · 시간대 표기 │
└───────────────┴─────────────────────────────────────────────┘

[SECTION 02] 스케줄 변경 피드      ← 변경 이력이 있을 때만 노출(없으면 섹션 자체가 숨김)
   필터(검색·종류·선사·초기화) + 시간순 변경 표(종류 배지 · B/L · 필드 old→new)

[SECTION 03] 등록 화물 자동 감시
   툴바(검색·선사·진행상태·구간·상태칩·정렬·필터초기화·[일괄 등록])
   그리드(12컬럼 · 관리자는 등록자 포함 13 · 20행 페이지네이션) + 행 확장(변경 타임라인 · ETA 드리프트 차트)

[서랍] 터미널·선사·항공 무료 조회 채널 — 우측 슬라이드 + 백드롭, ESC 닫기
[공통 푸터]
```

**레이아웃 판단 근거** — 조회창·감시 요약·채널을 좌측 레일에 고정한 것은 **결과를 보는 동안에도 다음 조회와
감시 상태가 시야에 남게** 하기 위함이다. 그리고 43개 링크의 바로가기 벽은 상시 노출에서 **서랍으로
강등**했다: 매번 쓰는 기능이 아닌데 화면 절반을 먹고 있어서 결과가 아래로 밀렸다(2026-08-19 개편).

## 3. SECTION 01 — 화물 조회 콘솔

### 3.1 좌측 레일

| 카드 | 구성 | 동작 |
|---|---|---|
| 화물 조회 | `#blNo` 입력 · [조회] 버튼(전폭) · 감지 힌트줄 | Enter = 조회. 입력 6자 미만이면 무반응 |
| 자동 감시 | 감시 건수 요약 · "매일 08:20 · 20:20 자동 조회" 안내 · [감시 그리드 보기 ↓] | 요약 숫자는 SECTION 03 목록과 같은 원천 |
| 채널 | [터미널·선사·항공 직접 조회 채널] 버튼 | 서랍 열기(§6) |

**감지 힌트줄**은 입력 번호를 판정해 세 갈래로 쓴다 — AWB 감지(프리픽스·항공사명) / 실조회 선사 감지
("운송 이벤트를 선사에서 직접 조회합니다") / 딥링크 선사 감지("이 선사는 공식 추적 페이지에서 확인합니다").
**조회를 누르기 전에 무엇이 일어날지 알려주는 것**이 목적이다.

### 3.2 결과 — 운송 관제 티켓

조회 결과는 카드 여러 장이 아니라 **티켓 한 장**이다. 섹션 레일(`SUMMARY`/`TERMINAL`/`GATE`/`HISTORY`)로
구획을 명시해 어디까지가 무슨 영역인지 눈으로 끊기게 한다.

| 영역 | 내용 |
|---|---|
| 헤더 | B/L 번호 · 선사명 · **상태 배지**(대기/운송중/완료) · 본선+항차 · **[추적 등록]** 버튼(이미 등록된 건은 `✓ 감시 중`) |
| SUMMARY | **요약 칼럼**(출발→도착 · ETA와 **D-day** · 다음 이벤트) + **Voyage Canvas** — 항구 노드를 잇는 인라인 SVG. 실적 구간 실선·예정 구간 점선, 선박 마커는 "마지막 실적 출발 ~ 다음 항 예정" 시간 보간 위치, 각 노드에 **A(실적)/E(예정) 칩**과 일시. 640px 이하에서는 **세로 타임라인으로 전환**(같은 데이터·다른 DOM, CSS가 가른다) |
| TERMINAL | 선명 + 한국 출항시각 ±4일 시간창으로 `bs_vessel_calls`(16터미널×35일)를 매칭해 **터미널 카드**를 붙인다: 터미널명·선석·접안·출항·**반입마감(CCT) 카운트다운**·**터미널발 변경 N회**(툴팁에 변경 내역)·**"소스 불일치" 배지**(선사 예정값과 12시간 이상 차이). **매칭 실패는 조용히 생략**한다 — 오탐 배지를 띄우지 않는 것이 원칙이다 |
| GATE | 컨테이너 × **정규 게이트 9슬롯 등폭 그리드**(공컨반출→적컨반입→선적→출항→환적→입항→양하→적컨반출→공컨반납). 출발지/도착지 그룹 헤더, 셀은 실적/예정/미발생 3색 + 날짜·시각 2단 스택. **표+가로스크롤이 아니라 등폭 그리드**라 컨테이너가 몇 건이든 열이 자동 정렬된다. 게이트 이벤트를 주지 않는 선사(COSCO)는 컨테이너 **최신 상태** 줄로 보완 |
| HISTORY | 컨테이너별 `<details>` 접기 — 전체 이벤트 목록(이벤트명·위치·야드·시각·예정 표기) |
| 푸터 | 데이터 시점(UTC)·출처 도메인·시간대 표기. **KST가 아닌 단일 오프셋이면 "시각 표기 UTC+3 — 선사 제공 시간대(한국시각 아님)"를 경고색으로 명시**한다(변환하지 않고 보이게 — 2026-08-19 결정) |

### 3.3 결과 — 딥링크 카드 / 빈 상태

- **딥링크 카드**: AWB, 또는 실조회 미지원 선사일 때. 제목·안내문 + [공식 추적 페이지 ↗]. 선사 미감지 시에는
  실조회 지원 목록을 안내한다.
- **빈 상태 카드**(`#ccEmpty`): 조회 전에만 표시하고 첫 조회에서 숨긴다. "무엇이 표시될지"를 미리 알린다.

## 4. SECTION 02 — 스케줄 변경 피드

내 감시 화물 **전체**의 최근 변경을 한 곳에 모은 시간순 표(KLNET HISTORY 그리드 대응).
종류 배지(출항·도착·모선항차·진행상태·게이트·**터미널**), B/L, `필드 · old → new`.

- **변경이 하나도 없으면 섹션 자체를 숨긴다**(빈 표를 보여주지 않는다).
- 단, **필터 결과가 0건일 때는 섹션을 유지**하고 "조건에 맞는 변경이 없습니다"를 표시한다 — 필터 때문에
  비었는지, 원래 없는지를 사용자가 구분할 수 있어야 하기 때문이다.
- 검색 입력은 재렌더 후 **커서 위치를 복원**한다(연속 타이핑 중 커서가 끝으로 튀지 않도록).

## 5. SECTION 03 — 등록 화물 자동 감시

선석배정 그리드와 같은 사상(툴바 필터 + 페이지네이션 20행).

| 구성 | 내용 |
|---|---|
| 헤더 | 감시 중 N건 / 전체 N건 · **관리자면 `관리자 · 전체 조회` 배지**, 일반 사용자는 `<본인> 등록분` · "매일 08:20 · 20:20 · ETD/ETA 변경 시 메일" |
| 툴바 | B/L·메모 검색 · 선사 셀렉트 · 진행상태 셀렉트 · 구간(항구) 검색 · 상태칩(전체/감시 중/종료) · 정렬(등록순·ETD·ETA·남은기간) · 필터 초기화(필터가 걸렸을 때만) · **[일괄 등록]** |
| 컬럼 | B/L · 선사 · 상태 · **알림(종 아이콘)** · 진행 · 구간 · ETD · ETA · 변경 · 남은기간 · (관리자만)등록자 · 최근 수집 · 조작 |
| 행 확장 | 변경 이력 타임라인(old→new·메일 발송 여부) + **ETA 드리프트 계단 차트**(폴링 회차별 ETA 변화·누적 슬립) |

**UX 규칙(전부 실사용 지적에서 나온 것)**

- **알림 종은 상태 옆 4번째 컬럼**이다. 이메일 전문 컬럼을 표 오른쪽 끝에 두었더니 가로 스크롤 없이는
  보이지 않아 "알림이 걸렸는지"를 아무도 확인하지 못했다. 종을 클릭하면 그 자리에서 수신 주소를
  등록·변경·해제한다(B/L 재조회 불필요).
- **종료 건의 종은 점선·흐림·disabled**로 표시하고 툴팁에 사유를 적는다. 종료(`active=false`)면 수집 자체가
  멈춰 실제로는 메일이 가지 않는데 종만 켜져 있으면 오해를 산다.
- **목록이 비어도 툴바를 그린다.** 빈 상태에서 [일괄 등록] 버튼이 사라지면 첫 등록 진입점이 없어진다.
- **네이티브 `alert`/`confirm`/`prompt` 를 쓰지 않는다.** 등록·해제·알림 설정·오류 표시 전부 사이트 모달
  (Enter 저장·바깥 클릭 닫기).
- **일괄 등록**: 줄바꿈·쉼표 구분 최대 500건, 추적 기간(3/6개월)·수신 이메일 선택, 결과는
  `등록 N건 · 실패 N건` + 실패 사유별 목록(형식 오류/중복/지원하지 않는 선사).

**권한** — 목록·등록·해제는 Edge Function `bl-watch` 경유이며(정적 사이트는 RLS로 DB 쓰기 불가),
세션 토큰을 서버가 `app_me` 로 검증한다. 일반 사용자는 자기 등록분만, 관리자는 전체. 비로그인은 빈 목록.
**같은 B/L 을 여러 계정이 각자 감시할 수 있다**(`unique(mbl_no, created_by)` — 2026-08-19).

## 6. 서랍 — 무료 조회 채널

우측 슬라이드 서랍 + 백드롭. 열림 시 `body` 스크롤 잠금, **백드롭 클릭·✕·ESC** 모두로 닫힌다.

| 그룹 | 수록 |
|---|---|
| 터미널 반출입·본선작업 | 전국 **16곳** — 부산신항 7 · 부산북항 2 · 인천 2 · 광양 2 · 평택당진 2 · 대산 1 + 통합(BPA 체인포털). 링크는 **선석배정 수집기가 실제로 긁는 화면 URL** 과 동일하다 |
| 선사 컨테이너 트래킹 | 해상 **17사** — 실조회 6사 + 딥링크 11사 |
| 항공 화물 | **10사** + 범용 조회(CHAMP·track-trace.com) — 국적사 2 · 외항사 6 · 특송 2 |

## 7. 인터랙션 규칙

- **Enter = 조회**, 입력 6자 미만은 무시. 번호는 영숫자 외 제거 후 판정.
- **`?no=` 딥링크**: 알림 메일의 "Open Cargo Tracking" 버튼이 이 경로로 들어온다. 입력창을 채우고
  **즉시 조회까지 실행**해 링크 한 번으로 결과 화면에 도달한다.
- **선사 목록 레이스 방지**: 화면은 기본 실조회 목록을 갖되 로드 시 `carrier-track?api=list` 의 live 목록을
  merge 한다(키 등록으로 선사가 늘어도 화면 재배포 불요). **merge 가 끝나기 전에 조회를 누르면** 새로 열린
  선사가 딥링크로 잘못 빠지므로, 조회는 목록 준비 Promise 를 기다린 뒤 실행한다.
- **다국어**: 신규 문자열은 전부 `data-i18n`(ko/en/zh 3언어 동시 등재).
- **접근성·모션**: SVG 는 `role="img"` + 라벨, 애니메이션은 `prefers-reduced-motion` 가드.
- **디자인 토큰**: `css/style.css` 기존 토큰 준수. 신규 클래스 프리픽스 — `cc-`(콘솔) · `tk-`/`trk-`(티켓)
  · `vc-`(Voyage Canvas) · `gs-`(게이트 그리드) · `tml-`(터미널) · `sc-`(변경 이력) · `wf-`(감시 그리드) · `ql-`(서랍).

## 8. 데이터 원천

## 9. 남은 과제

1. **선사 선택 폴백 UI** — `carrier-track` 은 `?carrier=` 를 이미 받는다. 자기식별이 안 되는 MBL(CMA그룹 등)이
   실조회 대상이 되면 화면에 선택 UI 추가.
2. **HBL→MBL 해석** — TAS 연계 또는 유니패스 `hblNo` 역추적.
3. **공유 링크** — 화물별 무로그인 추적 페이지(만료·회수 관리). 공개 정책 결정 대기.
4. **체화 위험(프리타임 D-day)** — 양하 후 경과일 버킷.
5. Figma 편집 좌석 확보 시 본 기획 이관(현재는 코드=디자인 시스템 토큰으로 직접 구현).
