> **현재 상태 요약(2026-08-19)**: 실조회 **6사**(ONE·COSCO·SM상선·Evergreen·SITC·**ZIM**) 가동 중.
> DCSA 어댑터 4사(머스크·하파그로이드·HMM·CMA)는 배포돼 있으나 키 미등록이라 딥링크 폴백 상태다.

## 1. 왜 만들었나

레거시 TWSC는 **KLNET PLISM 유료 API**(api.plism.com)로 MBL 추적 이벤트를 수집해
`KlnetTrackList` 화면(6밴드 53컬럼)에 표시한다. AI_SCM 포털의 cargo 탭은 이를 무료로 대체한다 —
사용자가 MBL을 입력하면 **선사 공개 트래킹 페이지의 백엔드 JSON API를 직접 호출**해
동급의 운송 이벤트 타임라인을 보여준다.

## 2. 레거시 파이프라인 (분석 결과 요약)

```
[부킹]  SeaBkgMgt: MBL_NO 수기입력 → OMS_BKG_MST → (House 생성 시) FMS_HBL_MST 복사
[등록]  SeaBkgList btnKLNETApi → TRK0002(bl_no, ref_no, carrier_code) → FMS_API_MST MERGE (시드)
[수집]  KlnetTrkAPIBatch(07·12시대): 기등록 MBL 중 ETD±3개월 && 공컨미반납 → TRK0003→TRK0005(20건 청크)
        → FMS_API_MST(BL)/FMS_API_TS(환적)/FMS_API_CNTR(컨테이너) delete-then-insert
[표시]  KlnetTrackList: FMS_API_* + 자사(FMS_HBL/MBL·OMS_BKG) LEFT JOIN → KLNET vs TAS_ 비교 표시
```

- **3레벨 데이터 모델**: BL(FMS_API_MST: POL/POD·VESSEL/VOYAGE·ETD/ATD·ETA/ATA·DIRECT_TS) ·
  환적구간(FMS_API_TS: SEQ별 항차, 화면은 2구간 절단) · 컨테이너 이벤트(FMS_API_CNTR: 게이트 이벤트 시각)
- **타임라인 캐논 순서**: 공컨반출(E_GATE_OUT) → 적컨반입(F_GATE_IN) → 출항(ETD/ATD) →
  환적₁…ₙ → 도착(ETA/ATA) → 적컨반출(F_GATE_OUT) → 공컨반납(E_GATE_IN) — 공컨반납이 추적 종료 판정
- **선사코드 4중 체계**: 자체 LINE_CD(LCMA·LONE…) / 표준 4자 `MDM_CARR_MST.KR_CUS_4CD`(CMDU·ONEY…) /
  KLNET carrier_code(CMAL·SSBF — SCAC과 다름) / BL 프리픽스. **KLNET조차 CMA그룹·완하이·SWIRE 6개
  선사군은 carrier_code를 별도로 받아야 했다** = 이들 MBL은 프리픽스 자기식별이 안 된다.
- 조회 키는 **MBL 단일**(bl_no). 시각은 YYYYMMDDHH24MISS 문자열, `0`/NULL = 미발생.

**핵심 교훈**: 안티봇은 URL이 아니라 **TLS 지문·IP 평판**을 본다. 이 PC(법인망 curl)에서 403이면
Edge Function(데이터센터 IP)에서도 403이다. 반대로 ONE·COSCO는 양쪽 다 열려 있음을 실측으로 확인했다.

## 4. 구현 (2026-08-11 · 2026-08-19 현행화)

- **Edge Function `carrier-track`** (verify_jwt=false — 무키 5사는 시크릿 불요, DCSA 계열만 키 필요) — datago의 화이트리스트 사상 계승:
  - `?no=<BL>&carrier=<SCAC?>` → 프리픽스 자동 감지, `CARRIERS` 맵에 등록되고 `ready()` 를 통과한 선사만 실조회
    (**live 6사: ONEY·COSU·SMLM·EGLV·SITC·ZIMU** / 키 대기 4사: MAEU·HLCU·HDMU·CMDU — 키 등록 시 재배포 없이 승격)
  - 미지원 선사 → `supported:false` + 딥링크 반환 (화면이 기존 딥링크 폴백)
  - 정규화 계약(레거시 3레벨 계승): `summary`(FMS_API_MST 상당) / `voyages[]`(FMS_API_TS 상당, **N구간 — 레거시의 2구간 절단을 계승하지 않음**) / `containers[].events[]`(FMS_API_CNTR 상당)
  - 이벤트 시각: `timeLocal`(항만 현지 — 기본 표시·레거시 관례) + `timeUtc`(보조), `actual` 불리언
  - `?api=list` = live/딥링크 선사 목록 소개
- **cargo 화면**: 선사 직접 추적 전용으로 재편 — 해상 MBL 감지(oceanInfo) 시 live 선사면 `#carrierOut`에 선사 운송 카드
  (구간 요약 → 항차 표 → 컨테이너별 타임라인·실제/예정 배지·현지시각), 미지원 선사·AWB는 공식 추적 딥링크 카드.
  **유니패스 통관조회는 화면에서 제외**(2026-08-11 사용자 결정 — Edge Function `track`은 보존만, 화면 미사용).
  SCAC 감지 정규식은 영숫자 완화(`[A-Za-z]{4}[A-Za-z0-9]{6,}`) — ONE 부킹오피스 문자 BL 대응(실측 버그 수정).
- **적용한 레거시 함정 대응**: 컨테이너 번호 영숫자 정규화 · 시각 미발생 생략 · 현지시각을 `new Date()` 변환
  없이 문자열로 표시(TZ 왜곡 방지) · E/A 구분 배지 · 신선도(fetchedAt·source) 표기 · 3단 방어 파싱 사상
- **화면은 그 뒤 두 번 더 나아갔다** — ① 등록 기반 **자동 감시·변경 알림** 계층(2026-08-11, `bl-watch`·`notify-bl`·스케줄러 ⑧)
  ② **관제 콘솔 UX 개편**(2026-08-19 — 좌측 조회·감시·채널 레일 / 우측 운송 관제 티켓, Voyage Canvas·국내 터미널
  교차검증·9열 게이트 그리드). 현재 화면 사양은 `docs/04-design/화면기획_화물추적.md`,
  고도화 설계는 `docs/03-architecture/화물추적_고도화_설계_2026-08-19.md` 를 볼 것.

## 5. 남긴 것 (로드맵) — 2026-08-19 진척 반영

1. ~~**COSU 필드 매핑 확정**~~ **완료(2026-08-11)** — 실 COSCO BL 8건으로 대조해 `trackingPath`·`actualShipment` N구간·실제/예정을 실물 기준 재매핑(0/8 → 8/8). 게이트 이벤트는 bill 응답에 전건 null 이라 `containers/{cntrNo}` 의 `containerCircleStatus` 로 최신 상태를 보조 조회한다.
2. ~~**Evergreen·SM상선 어댑터**~~ **완료(2026-08-11)** — Evergreen 은 ShipmentLink `TYPE=BL`+`TYPE=CntrMove` HTML 파싱(hex 엔티티 디코드·MON-DD-YYYY 변환), SM상선은 `CUP_HOM_3301GS.do` f_cmd 121→124→125 스테이트리스 JSON. **장금상선은 계속 불가** — 봇 차단이라 공개 페이지 어댑터를 만들지 않는다는 원칙(§3)에 해당하며, 열려면 사무실 PC Playwright 트랙이 필요하다.
3. **선사 선택 폴백 UI** — 미구현. `carrier-track` 은 `?carrier=<SCAC>` 를 이미 받으므로 **백엔드는 준비돼 있고 화면만 없다.** 자기식별이 안 되는 MBL(CMA그룹 등)이 실조회 대상이 되는 시점에 추가한다.
4. **멀티 조회**(레거시 M 모드: 줄바꿈 입력→IN) — **감시 등록 경로로 충족(2026-08-11~19)**: `bl-watch?action=bulk` 로 줄바꿈·쉼표 구분 **최대 500건 일괄 등록**(실패는 사유별 표시), 등록분은 감시 그리드(검색·선사·진행상태·구간·정렬·페이지네이션)와 스케줄 변경 피드에서 한 화면으로 본다. **단건 조회 입력창에 여러 B/L 을 넣어 동시 조회하는 형태는 여전히 없다** — 다건 수요는 "등록해두고 자동으로 본다"로 흡수됐다.
5. **HBL→MBL 해석** — 미구현. TAS 연계 또는 유니패스 `hblNo` 조회로 MBL 역추적.
6. **캐시(TTL)·레이트리밋** — 부분 대응. 조회 함수에는 캐시가 없고, 대신 수집기(⑧)가 **적응형 폴링**(near 3h·transit 12h·pre 24h·실패 30분)과 **선사 인터리브**로 호출량을 눌러 SITC 429 를 피한다. "빈 응답은 기존 데이터 보존" 원칙(레거시 결함 §3-7 교훈)은 유지 — 빈 응답이 스냅샷을 덮지 않는다.
7. **TAS 자사값 비교(TAS_ETD vs 선사 ETD)** — 미구현(Oracle 연계 별도 과제). 다만 **국내 구간 교차검증은 다른 재료로 먼저 구현됐다** — 선사 예정값과 `bs_vessel_calls`(16터미널 선석) 값이 12시간 이상 어긋나면 "소스 불일치" 배지를 띄운다(2026-08-19 P5).
