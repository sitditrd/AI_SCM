## 실행 모델

- 예약 시각이 되면 해당 앱이 **자율 Claude 세션을 자동 기동**하고, 그 세션이 지침(SKILL.md)대로 .py 실행·MCP 적재·검증·결과 보고까지 수행한다.
  ②③④의 지침 파일: `C:\Users\Administrator\.claude\scheduled-tasks\<작업ID>\SKILL.md`
- **service_role 키가 PC에 저장되지 않는다** — .py는 SQL 파일만 생성하고, DB 쓰기는 Claude 세션이 Supabase MCP로 실행한다(--sql 모드).
- 모든 적재는 **동일 수집일 delete 후 insert(멱등)** — 재실행·중복 실행에 안전하다.
- **앱이 켜져 있어야 실행된다.** 꺼져 있으면 다음 앱 실행 시점에 밀린 작업이 돈다. 절전 모드 방지 옵션을 켜둘 것.
  ②는 최근 7일 **건수 비교** 방식이라 미적재·부분적재 날짜를 자동 복구한다(2026-08-02·08-03분이 08-03 09:10~09:27에 캐치업된 실적 있음).
  다만 **정시(08:03) 보장은 되지 않으므로**, 아침 일찍 화면을 봐야 하면 아래 이중화를 병행한다.

### ②의 정시 보장 이중화 (선택 — Windows 작업 스케줄러)

앱 실행 여부와 무관하게 OS가 직접 적재하는 경로. 동일 수집일 replace(멱등)라 앱 스케줄러 ②와 중복 실행돼도 데이터가 깨지지 않는다.

```bat
REM 1) 시스템/사용자 환경변수에 SUPABASE_SERVICE_KEY 등록 (Supabase → Settings → API → service_role)
REM 2) 작업 등록 (06시 수집 직후인 06:40 권장)
schtasks /create /tn "TWL_BerthUpload" /tr "\"<REPO>\scripts\run_berth_upload.bat\"" /sc daily /st 06:40 /f
```

- 실행 로그: `logs/berth_upload.log` · 키 미설정 시 조용히 SKIP(오류 아님)
- 수동 1회 실행: `python scripts\upload_berth_sql_parts.py --rest --today`
- **트레이드오프**: 이 경로만 service_role 키를 PC에 저장한다(기본 설계는 키 미보관). 키를 두지 않으려면 등록하지 말고 앱 스케줄러 캐치업에 의존한다.
